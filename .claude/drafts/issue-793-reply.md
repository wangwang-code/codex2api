感谢反馈和日志！排查下来，根因是**上游的客户端版本闸**，不是套餐限制，也不是测试账号被路由走了。

## 根因

上游对“账号套餐没有这个模型”和“请求带的客户端版本太低”这两种情况，返回的是**同一句**错误：

> The 'gpt-6.1-sol' model is not supported when using Codex with a ChatGPT account.

我们用一个 pro 账号按客户端版本逐个拉上游模型清单（`/backend-api/codex/models?client_version=…`）：

| client_version | 清单里有没有 gpt-6.1-sol |
| --- | --- |
| 0.153.0 ～ 0.158.0 | 没有 |
| 0.159.0 及以上 | 有 |

也就是说 gpt-6.1-sol **实际要求客户端版本 ≥ 0.159**，而清单里它自己声明的 `minimal_client_version` 是 0.153.0（这个声明不准）。网关内置的模拟版本当时是 0.153.3，所以只要版本同步没成功、或者出站版本被固定在 0.159 以下，**所有套餐**的账号都会报这个错。ChatGPT 网页端能用，是因为网页和 Codex 走的是两套准入。

关于你贴的 AI 分析，补充说明三点：

- **三个 free 号都报错，不代表是 free 套餐的问题。** 版本过低时，free / plus / pro 都会返回同样的错误。上游清单里 gpt-6.1-sol 的 `available_in_plans` 包含 free、plus、pro。
- **`api_key_auth_available=1` 不是“只开放给 API key”的意思。** 它只是后台展示用的元数据，不参与路由；gpt-6.1-sol 显示为 1 是内置表漏标了，这次已顺手修正。
- **后台「测试连接」只会用你选中的那个账号**，不走调度，也不重试。日志里 551 → 600 → 613 的换号，是普通 API 请求的重试。

**为什么点了“同步最新客户端”还是不行：** 旧版本网关把这个 400 当成套餐问题，给每个失败的账号写了 30 分钟的“不支持模型冷却”（会落库，重启也还在）。同步完版本后这些冷却并不会被清掉，号池全在冷却里时，网关返回的错误第一句和上游原文一模一样，看起来就像同步没起作用。另外，如果出站版本被固定了（见下面第 3 步），同步也改不了它。

## 修复内容（4365b7cd，已合入 main，会随下一个版本发布）

1. **内置版本提到 0.160.0**：内置 Codex CLI 版本和「最低 CLI 版本」默认值从 0.153.3 提到 0.160.0，桌面端 / VSCode 形态的内置版本配对也补到 0.160.0。即使版本同步失败，也能越过这道门槛。
2. **同步后自动清冷却**：版本同步一旦抬高了版本，会自动清除已有的“不支持模型冷却”。
3. **区分版本闸和套餐闸**：Pro 档账号也报这个错时，判定为客户端版本过低，不再给账号写冷却；之后同一模型、同一出站版本下其他账号的同类失败也不冷却。真正的套餐限制仍按（账号, 模型）冷却，照常换号。
4. **日志带上出站版本**，例如：`账号 X (plan=pro) 请求模型 gpt-6.1-sol 被上游拒绝，判定为客户端版本过低（出站 Version=0.153.3），不写入模型冷却…`，方便直接看出是不是版本问题。

## 升级前的临时绕过办法

1. **同步客户端版本**：「设置 → Codex → Codex 客户端版本同步」点「立即同步」，确认当前模拟版本 **≥ 0.159**（目前最新是 0.160.0）。同步失败一般是服务器连不上 GitHub 或官方源，配好全局代理后再同步。
2. **清掉已有的冷却**（同步完必须做这一步）：「设置 → 通用设置 → 不支持模型冷却」临时改成 `0` 并保存，会自动清除已有冷却；确认能用之后再改回原值（默认 1800）。也可以到账号详情里，对 gpt-6.1-sol 点「清除此模型冷却」。
3. **检查出站版本是否被固定**：
   - 如果在「设置 → Codex」的 User-Agent 配置里填了「原始 User-Agent 覆盖」或「客户端版本」，网关会原样使用其中的版本，同步不会改它们，需要改到 ≥ 0.159 或清空。
   - 如果下游用的是官方 Codex CLI / 桌面端，并且兼容模式是「保留客户端」，网关会透传客户端自己的版本。可以把客户端升级到 ≥ 0.159；或者把兼容模式改成「自动兼容」，再把「最低 CLI 版本」设为 0.160.0（可以直接点「设为同步版本」）。
4. **自查**：使用记录里这条请求的「上游 UA」中的版本号，就是实际发给上游的版本。确认它 ≥ 0.159 后再测。

如果按上面处理（或升级后）还是报同样的错误，麻烦补充这些信息：codex2api 版本、设置里显示的当前模拟版本、使用记录里这条请求的「上游 UA」、下游客户端类型和版本。特别是 free 号：清单显示 free 套餐包含这个模型，但我们手上没有 free 号能实测，如果版本够了 free 号仍然报错，也请告诉我们。
